# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
# Install dependencies
pip install -r scraper/requirements.txt

# Run the full pipeline locally (~10-15 min for ~25-30k listings)
python scraper/pf_scraper.py      # Step 1: Scrape API → data/raw/
python scraper/cleaner.py          # Step 2: Raw JSON → CSVs in data/latest/
python scraper/comparator.py       # Step 3: Diff vs previous snapshot → data/changes/
python scraper/reporter.py         # Step 4: Generate data/latest_report.json
python scraper/quality_gate.py     # Step 5: Validate quality (exits 1 on failure)
python scripts/update_dashboard.py # Step 6: Regenerate dashboard/data.json

# Quality gate with verbose output
python scraper/quality_gate.py --detailed

# Regenerate dashboard data only (no scrape needed)
python scripts/update_dashboard.py
```

No tests exist in this repository.

## Architecture

**Daily PropertyFinder Bahrain market intelligence pipeline.** Scrapes ~25-30k listings and tracks market changes (new listings, removals, price changes) over time for Power BI / AI training use.

### Data flow

```
API (__NEXT_DATA__ in Next.js HTML)
  → data/raw/*.json                         (gitignored, large)
  → data/raw_archive/YYYY-MM-DD/*.json.gz   (gzip-compressed, committed)
  → data/latest/*.csv                       (flat 116-column CSVs, committed)
  → data/previous/*.csv                     (yesterday's snapshot, for diffing)
  → data/changes/*.csv                      (cumulative + daily change logs)
  → data/latest_report.json                 (pipeline health summary)
  → dashboard/data.json                     (generated by update_dashboard.py)
```

### Scripts

**`scraper/pf_scraper.py`** — Two-phase scraper:
1. Discovery: reads HTML pages via BeautifulSoup to find subcategory URLs (drills down until ≤1,250 listings per URL)
2. Scraping: 4 parallel workers, 0.5s base delay + 0.5s jitter. Hits the JSON embedded in `__NEXT_DATA__` script tag on each page. Deduplicates by `record.get("id")`.

**`scraper/cleaner.py`** — Flattens raw JSON into flat CSVs. Critical detail: the live API wraps each listing as `{listing_type: "property", property: {snake_case fields}}`. The cleaner handles **two formats**:
- **Live format** (from `__NEXT_DATA__`): nested snake_case under `property` sub-object — `property.price.value`, `property.location.coordinates.lat`, `property.agent.is_super_agent`, `property.location_tree[...]`
- **Flat format** (test/uploaded data): top-level camelCase keys — `propertyType`, `agentInfo`, etc.

Format is auto-detected. Boolean fields use a `bk(*keys)` helper to safely read without Python's `or` chain dropping `False` values. `location_tree` (underscore) contains `REGION`, `AREA`, and `COMMUNITY` nodes — community nodes are extracted separately; level-1 COMMUNITY is promoted as `area_name` when no AREA node exists.

`COLUMNS` (116 fields) and `PROJECT_COLUMNS` (132 fields) define the exact output schema — this is the contract with downstream consumers (Power BI, n8n `pf_listings` table). **Do not reorder or remove columns without updating downstream.**

**`scraper/comparator.py`** — Diffs `data/latest/` vs `data/previous/`, writes `data/changes/YYYY-MM-DD.csv` and appends to `data/changes/all_changes.csv`. Rotates latest → previous at the end.

**`scraper/quality_gate.py`** — Validates 5 critical fields (listing_id, price_value, latitude, longitude, title) at 95% threshold. Also checks price ranges and row count (minimum 20,000). Writes `data/latest/quality_report.json` and `.md`. Run with `--detailed` for per-category breakdown, `--report-only` to print without gating.

**`scraper/reporter.py`** — Reads CSVs and writes `data/latest_report.json` with category counts, change summaries, and pipeline health.

**`scripts/update_dashboard.py`** — Reads all pipeline outputs and writes `dashboard/data.json`. Also calls the GitHub Actions API (using `GITHUB_TOKEN` env var) to classify recent workflow runs as real failures vs cosmetic no-ops (zero jobs spawned = cosmetic). Uses `urllib.request` (not `requests`) so it runs in the `update_dashboard.yml` workflow without extra pip installs. Anomaly warnings only fire if the **most recent** run conclusion is still `failure` — historical failures that self-recovered are surfaced in `actions_health` but do not trigger the status alert.

**`scraper/timing_analysis.py`** — One-time use; analyzes timing study results. Study is complete; optimal window confirmed as 20:00 UTC.

**`scraper/update_handover.py`** — Appends entries to `HANDOVER.md`. Called automatically by GitHub Actions after each run.

### GitHub Actions workflows

| Workflow | Trigger | Purpose |
|---|---|---|
| `daily_scrape.yml` | `cron: 0 20 * * *` + manual | Full pipeline: scrape → clean → compare → report → quality gate → archive → commit |
| `update_dashboard.yml` | After daily scrape + manual | Runs `scripts/update_dashboard.py`, commits `dashboard/data.json`, triggers Pages deploy |
| `timing_study.yml` | Disabled (study complete) | Was: every 4h for 7 days to find optimal scrape time |

### Dashboard

`dashboard/index.html` is a static single-page app. It fetches `dashboard/data.json` at load time and renders: pipeline status, category counts, 14-day change trend, field fill rates, anomaly alerts, and Actions run health. Hosted on GitHub Pages at `bader1919.github.io/pf-pipeline/dashboard/`.

`dashboard/data.json` is committed to the repo and served as a static file — no server needed.

### Known permanent gaps (not bugs)

These columns are always 0% — PF Bahrain doesn't expose them in the API:
`age`, `agent_license_no`, `rera_number`, `rera_authority_name`, `broker_license_number`, `zone_name`, `share_url_translated`, `mortgage_cashback`, `rental_availability_date`

Partial-fill columns are correct by design:
- `bedrooms/bathrooms` — commercial listings omit these (~84%)
- `completion_status` — only off-plan properties (~25%)
- `community/sub_community` — only master-planned developments (~25% / ~3%)
- `payment_methods` — only some listings (~40%)

### Raw data archiving

`data/raw/` is gitignored. After each scrape, raw JSON is gzip-compressed (~85% smaller) to `data/raw_archive/YYYY-MM-DD/*.json.gz` and committed. To re-clean a past archive:

```bash
DATE=2026-06-09
mkdir -p data/raw
for f in data/raw_archive/$DATE/*.json.gz; do
  gzip -d -c "$f" > "data/raw/$(basename $f .gz)"
done
python scraper/cleaner.py
```
